# FSD v2.1 and TanStack Query Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the standalone Next.js application to official FSD v2.1 and align its existing TanStack Query integration with the official FSD React Query guide without changing behavior.

**Architecture:** Root `app/` remains the Next.js App Router and re-exports FSD page slices from `src/_pages`. Application initialization, providers, shell, fonts, styles, QueryClient construction, and global async-error handling live in `src/_app`. Page-specific workflows and the single activity query live in their owning `_pages` slices; generic HTTP and UI infrastructure remain in `src/shared` behind segment public APIs.

**Tech Stack:** Next.js 16.2.10, React 19.2.7, TypeScript 7.0.2, TanStack Query 5.101.2, Zod 4.4.3, Bun 1.3.14, Vitest 4.1.10, `steiger` 0.6.0 with `@feature-sliced/steiger-plugin` 0.7.0.

## Global Constraints

- Preserve `/`, `/login`, `/dashboard`, and `/settings` behavior, metadata, loading, error, not-found, accessibility, and responsive behavior.
- Preserve pre-existing `.gitignore` work and all unrelated changes.
- Add only the `steiger` core/CLI and `@feature-sliced/steiger-plugin` FSD rules packages as exact dependencies, plus their lockfile change.
- Do not add features, entities, widgets, backend behavior, authentication, persistence, mutations, pagination, Suspense queries, or server hydration.
- Do not stage or commit.
